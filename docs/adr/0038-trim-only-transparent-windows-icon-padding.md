# ADR 0038: Trim only transparent Windows icon padding

The white application carrier and its foreground have an approved proportion. Windows-specific sizing may only reclaim transparent space outside that complete artwork; do not enlarge the internal mark, redraw the carrier, thicken strokes, or discard any nonzero-alpha edge or shadow. All approved macOS application and menu-bar resources remain byte-identical.

Generate a Windows-only runtime PNG by copying the complete 1024px application artwork into its smallest square alpha bounds plus a one-source-pixel guard. The current crop is 983×983px at (21, 20), so native downscaling makes the complete icon approximately 4.2% larger. Both foreground and background retain their original coordinates relative to one another. Windows windows select this PNG explicitly; other platforms retain `icon.png`. Application ICO frames at 32px and above, and tray frames at 32px and above, are uniformly scaled from the cropped artwork. Retain the existing application ICO sizes and its 16px artwork; preserve the existing 16/20/24px tray frames, which lack a complete transparent perimeter. Do not change document association icons.

`node scripts/generate-windows-icons.mjs` updates only Windows resources. Tests verify that every discarded source pixel is fully transparent, retained alpha and opaque colors are unchanged, generated frames scale the entire cropped image, small frames remain unchanged, and macOS asset hashes are fixed. This is a bounded visual adjustment, not a claim that the reported Windows runtime sizing cause has been diagnosed; Windows native visual acceptance is still required.
