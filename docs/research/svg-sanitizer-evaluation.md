# HTML/SVG 清理器评估

> 调研日期：2026-08-29。仅引用项目官方文档、源码、测试与安全公告。

## 结论

Fuxian 现在确实有一部分**自研清理器**，但不是从零替代成熟库：

- Markdown 正文已经通过 `rehype-sanitize` 的 GitHub 风格 schema 清理，并额外限制 `href`/`src` 协议（[`packages/markdown-renderer/src/index.ts`](../../packages/markdown-renderer/src/index.ts)）。
- 图表渲染结果则由 `sanitizeRenderedVisualSvg` 直接解析 DOM，删除危险元素、事件属性、外部 URL，并给 Infographic 的 `foreignObject > span` 配置独立结构与 CSS 白名单（[`finished-document.ts`](../../apps/desktop/src/renderer/src/finished-document.ts)）。

**推荐：正文继续使用 `rehype-sanitize`；图表 SVG 改为“DOMPurify 基线 + Fuxian 按图表类型的策略层”。** DOMPurify 负责浏览器解析差异、SVG/HTML 命名空间、mutation XSS、DOM clobbering 和危险 URL 等通用安全问题；Fuxian 仍负责元素数量上限、禁止联网、unwrap 链接，以及 Infographic/D2 各自允许的 XHTML 和 CSS。不要把 D2 的 `foreignObject` 全局放开。

## 现有实现的优缺点

现有 SVG 清理代码很容易理解，也已经做对了几件产品相关的事：只接受单个 `<svg>`、限制 100,000 个元素、移除可加载资源的元素、只允许 fragment URL，并对 Infographic 文本使用精确结构/CSS 白名单。这些不是通用 XSS 库能替 Fuxian 决定的。

不足是通用 SVG 安全边界由少量 selector 和正则承担：没有验证元素/属性 allowlist 与实际 namespace，没有覆盖 SVG 动画对 URL 属性的间接赋值，也没有系统处理浏览器重解析/mutation XSS。继续独自维护这层，测试成本会随 D2 的 SVG/XHTML/CSS 表面显著增长。

没有发现一个独立、成熟、浏览器端且比 DOMPurify 更适合 D2 `foreignObject` 的 SVG 专用清理引擎。SVGO 一类优化器的职责是变换/压缩 SVG，不应当当作安全 sanitizer。

## D2 接入时的建议结构

1. 为每种图表定义不可变 policy：`mermaid`、`plantuml`、`vega-lite` 默认纯 SVG；`infographic` 和未来 `d2` 才允许受控 XHTML。
2. 用 DOMPurify 的显式 `ALLOWED_TAGS`/`ALLOWED_ATTR`、允许的 namespace、`ALLOW_DATA_ATTR: false`、`ALLOW_ARIA_ATTR: false`，返回新 `DocumentFragment`；不要依赖默认宽松 profile，也不要 `IN_PLACE`。
3. D2 policy 只开放渲染器实际输出的 `foreignObject` 子树。原始 D2 Markdown 里的任意 HTML不能因为 D2 生成了它就自动可信。
4. CSS 单独用成熟 parser 解析后按 property/value 白名单重建；禁止 `@import`、外部 `url()`、自定义字体加载、定位逃逸和交互行为。DOMPurify 本身不是 CSS policy engine。
5. 保留现有元素/字节上限、只允许 `#fragment` URL、链接 unwrap、CSP 与屏幕/PDF 共用同一清理后快照。再用 DOMPurify 官方 SVG/mutation 测试向量和各渲染器真实 fixture 做回归。

这会把“浏览器安全细节”交给专门团队维护，同时不牺牲 Fuxian 对离线、隐私和渲染完整性的严格要求。
