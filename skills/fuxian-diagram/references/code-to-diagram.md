# 从源码与配置提取图示

用于解释实际系统。目标不是把所有文件画出来，而是以可追溯证据回答用户的问题。用户是在设计新系统时，应把建议与当前实现分开标注。

## 证据映射

| 证据                          | 可支持的内容                 | 不能直接推断                 |
| ----------------------------- | ---------------------------- | ---------------------------- |
| 路由/事件入口与调用实现       | 请求时序、输入检查和异常出口 | 每个依赖都会在本次请求中调用 |
| import、接口、模块定义        | 类型与模块依赖               | 独立进程、网络请求或真实部署 |
| 状态字段赋值和迁移条件        | 生命周期、守卫条件           | 从名称猜所有合法迁移         |
| schema、迁移、约束            | 实体、主外键、基数与可空性   | 仅凭字段后缀判断唯一性       |
| 队列发布/订阅、确认与重试配置 | 异步消息、消费边界、重投行为 | 恰好一次执行或天然幂等       |
| Compose、Kubernetes、IaC      | 实例、网络、存储、部署边界   | 配置一定已发布到生产         |
| 现有测试与夹具                | 特定场景的预期行为           | 未覆盖场景也有同样保证       |

## 提取路径

从与用户问题有关的入口开始，沿主要调用链读取分支、数据结构和配置。为每个节点/关键边保留文件或段落依据；关注成功路径之外的输入拒绝、资源不可用与已定义的异常处理。

例如解释“导出失败后会发生什么”，应查导出入口、就绪判定、渲染失败处理和返回状态，而不是将整个应用目录转成架构树。

## 选择视图

- 谁调用谁、何时返回：时序图。
- 条件决定下一步：活动图。
- 某对象何时转到新状态：状态图。
- 模块职责与契约：组件/类/包图。
- 运行位置与通信：部署图。

同一份源码可以支持多种视图，只交付回答当前问题所需的视图。框架惯例与上游模板是帮助阅读的线索，不是待复制的事实。

## 交付校验

逐边核实方向与含义。同步/异步、事务边界和失败条件必须有证据，缺失处说明未知。精简图时可以合并内部细节，但不能删掉会改变用户理解的异常路径。正文附关键源码位置，让图能随实现更新。
